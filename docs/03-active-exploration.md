# 主动探索机制

## 1. 目的与行为准则

主动探索的目的，是在不增加不必要用户负担的前提下，把用户提供的 URL、截图、录屏、源码、设计文件和素材转换成足以严格复刻的证据。

Agent 必须遵循：

1. **先探索，后询问**：能通过现有工具安全获得的信息，不先让用户手工整理。
2. **先广度，后深度**：先找全页面、主题、组件和断点，再深入测量高价值样本。
3. **自动但不鲁莽**：默认只读；不绕权限、不触发有副作用操作、不执行未知脚本。
4. **每一步可追溯**：工具、参数、时间、环境、输入和输出写入探索日志。
5. **主题成对采集**：尽量在同一路由、同一视口、同一状态采集 light/dark 对。
6. **探索驱动待办**：每轮结束更新覆盖矩阵、gap、TODO 和用户请求。
7. **不以工具缺失伪装完成**：无法自动截图或提取时记录限制，并请求替代输入。

## 2. 探索状态机

每轮按以下状态执行并记录：

```text
INTAKE → SAFETY_CHECK → DISCOVERY → CAPTURE_PLAN → ACQUISITION
       → EXTRACTION → SYNTHESIS → VALIDATION → GAP_CLOSURE
       → COMPLETE 或 WAITING_FOR_INPUT
```

### INTAKE

- 识别输入类型、档案 ID、系统版本和用户目标。
- 计算本地文件哈希，保留原名和原件。
- 建立 `manifest.json`、来源索引、探索日志、覆盖矩阵、TODO 和 REQUESTS。

### SAFETY_CHECK

- 判断 URL 是否公开/需登录，源码是否可信，是否存在隐私或授权限制。
- 检查工具可用性和运行成本；先读 `09-security-rights.md`。

### DISCOVERY

- 枚举页面、主题、断点、组件、状态、资源和可用源码，不急于生成 Token。
- 找出代表性页面和高复用组件。

### CAPTURE_PLAN

创建明确矩阵：`route/component × theme × viewport × state × artifact`，标注必需、可选和当前缺口。先覆盖核心路径，再扩展长尾。

### ACQUISITION / EXTRACTION

按输入分支执行第 4–8 节；原始资料进入 `sources/`，派生资料进入 `evidence/`。

### SYNTHESIS

在证据足够后归纳基础、主题、布局、组件、模式和 Token。观察、推断、建议分离。

### VALIDATION

运行语法、引用、主题一致性和视觉回归检查。比较环境必须可复现。

### GAP_CLOSURE

Agent 先尝试用其他已有输入交叉验证；仍不能关闭时才写入 REQUESTS 并集中询问用户。

## 3. 工具发现与选择

Agent 不应假设某个工具一定存在，应先检查环境和项目已有依赖。按任务优先选择：

- **浏览器自动化**：现有 browser 工具、Playwright、Puppeteer、Selenium；用于导航、主题切换、状态操作、截图、DOM 与计算样式。
- **浏览器诊断**：DevTools Protocol、页面脚本、可用的无头浏览器；用于 CSS 变量、布局盒、字体、动画和资源信息。
- **网络/静态获取**：`curl`、`wget` 或等价工具；仅用于授权公开资源和响应头，不绕过限制。
- **文件与源码检索**：`find`、`rg`、语言 AST 工具、包管理器只读命令。
- **图片分析**：Pillow、OpenCV、ImageMagick、`exiftool`；用于尺寸、色彩、几何、差图和元数据。
- **OCR**：系统 OCR、Tesseract 或已有视觉工具；结果只作辅助，必须抽样核对。
- **字体**：浏览器 FontFace/计算样式、fonttools、`fc-scan`、`otfinfo` 等已有工具。
- **视频/动效**：`ffprobe`、`ffmpeg`；提取帧、时长和节奏。
- **JSON/CSS 校验**：`jq`、语言解析器、stylelint 或项目已有测试。

选择原则：优先已有、可重复、低侵入工具。不要为了探索而全局安装依赖；需要大型下载、浏览器安装、付费 API 或系统修改时先征求用户同意。工具不可用时记录尝试、错误和替代方案。

## 4. 用户提供网站 URL 时

### 4.1 建立访问基线

1. 记录原 URL、最终跳转 URL、时间、页面标题、系统版本线索和访问条件。
2. 记录浏览器名称/版本、操作系统、locale、时区、缩放、DPR、viewport、颜色方案和是否登录。
3. 保存首个原始 viewport 截图和 full-page 截图，确认页面可达且没有错误页/登录墙。
4. 检测主题来源：页面开关、`prefers-color-scheme`、HTML class/data attribute、本地存储或 URL 参数。
5. 主题切换后等待字体、图片、异步数据和动画稳定，再截图；记录等待条件，避免任意 sleep 成为唯一稳定机制。

### 4.2 页面与组件发现

在不触发破坏性行为的情况下：

- 读取顶栏、侧栏、页脚、面包屑、tab、站内链接和路由配置线索；
- 检查 `sitemap.xml`、公开导航、静态路由和 Storybook/组件文档（若公开）；
- 去重带追踪参数、分页和相同模板 URL，避免无限爬取；
- 标记登录、编辑、删除、付款等不可安全探索路径；
- 识别页面类型：登录、工作台、列表、详情、创建/编辑、设置、搜索、异常/空状态；
- 识别重复组件及各页面独有组件；
- 记录桌面/移动导航模式和可能断点。

输出到 `analysis/inventory.md` 和 `analysis/coverage-matrix.md`。站点很大时按“壳层 + 每类页面至少一个代表 + 核心组件状态”采样，不需要盲目抓取每条业务数据详情。

### 4.3 自动截图矩阵

若浏览器自动化可用，创建可重复脚本或记录等价步骤。至少考虑：

- 主题：`light`、`dark`；
- 视口：来源明确的实际断点；未知时先用代表性桌面 `1440×900` 和移动 `390×844`，再通过布局变化探索真实断点；
- 页面：全局壳层和每类核心页面；
- 状态：default、hover、focus-visible、active、selected、disabled、loading、error、empty、open/closed；
- 截图：viewport 与 full-page；关键浮层/组件另做局部截图；
- DPR：优先固定为 1 便于像素测量；若来源依赖高 DPR，明确记录；
- 稳定性：关闭非必要随机内容，等待字体和资源；动效截图需固定时刻或临时暂停动画，但原始动效另录屏。

截图文件名：

```text
<route-or-component>__<theme>__<viewport>__<state>__<sequence>.png
# dashboard__light__1440x900__default__01.png
# select__dark__390x844__open-focus__01.png
```

每张写入 `capture-manifest.json`：证据 ID、URL、主题、视口、DPR、浏览器、locale、状态、全页/局部、时间、SHA-256、稳定条件和本地路径。

### 4.4 主动操作状态

- hover：在精确元素中心触发并确认 `:hover` 样式生效；
- focus：优先真实键盘 Tab 触发 `:focus-visible`，不能只调用 focus 后假设一致；
- active：使用安全的按下但不提交方式；
- disabled/loading/error：优先组件文档、测试页、安全 mock 或已有页面状态；
- 菜单/弹窗/抽屉：记录触发器、overlay、层级、进入/退出动效、焦点陷阱和关闭方式；
- 表单：只用虚构数据，不提交到真实后端；
- destructive/付费动作：不触发，改用源码、组件文档或用户截图。

### 4.5 DOM、CSS 与资源提取

对代表页面和核心组件主动收集：

- HTML 根主题标记、语义结构和组件边界；
- CSS 自定义属性及其 light/dark 作用域；
- 关键元素 `getComputedStyle`：字体、颜色、background、border、radius、shadow、opacity、transform、transition、animation、z-index；
- `getBoundingClientRect`：位置、宽高、内外间距推导和对齐；
- 伪元素 `::before/::after` 的计算样式；
- 实际字体加载状态、font-family、weight 和 FontFace 来源；
- SVG viewBox、stroke、fill、尺寸；
- 图片自然尺寸、显示尺寸、object-fit、比例和滤镜；
- stylesheets 和 sourcemap 线索（仅公开/授权内容）；
- media/container query、断点、hover/pointer 条件；
- animation/transition 参数和 reduced-motion 分支。

提取结果保存为结构化 JSON 或 Markdown 到 `sources/computed-styles/`，注明选择器/组件、主题、视口和来源。不要只保存最终色板而丢失元素语义。

### 4.6 响应式断点探索

不要只截两个尺寸。先从 CSS/media query 或源码找候选断点，再在断点前后各测试至少 1px 或合理邻域，观察：导航切换、列数、容器宽度、间距、字体、表格、浮层和触控行为。记录“连续缩放”与“离散切换”的差异。

### 4.7 网站探索结束条件

至少完成两轮：第一轮覆盖页面类型与主题，第二轮补齐组件状态和断点。以下任一情况进入 `WAITING_FOR_INPUT`：登录/权限阻塞、另一主题不可达、关键状态不可安全触发、字体/源码受限或浏览器工具不可用。不得把错误页截图当真实页面。

## 5. 用户提供截图时

### 5.1 原件检查

1. 原样保存，计算 SHA-256；不覆盖、不重压缩。
2. 记录像素尺寸、格式、色彩空间、alpha、EXIF、可能缩放和压缩痕迹。
3. 识别主题、页面、视口、设备、DPR、浏览器和状态；未知字段明确写 unknown。
4. 检查是否裁切、拼接、带浏览器边框或经过聊天工具缩放。
5. 尝试与其他截图配对：同页面 light/dark、同主题不同视口、同组件不同状态。

### 5.2 分层分析

按从大到小顺序：

1. **页面壳层**：画布、顶栏、侧栏、内容容器、浮层和滚动区域；
2. **几何**：边界、栅格、列宽、gutter、对齐、基线和留白；
3. **字体**：OCR 辅助识别文本角色，测量字号/行高仅在缩放已知时作为可靠值；字体家族仅凭图片通常低置信；
4. **色彩**：按语义区域取样，不把抗锯齿像素当 Token；区分实色、透明叠加、渐变、阴影和图片色；
5. **组件**：裁切代表组件，标注 anatomy、尺寸、内边距、圆角、边框、图标和状态；
6. **层级与效果**：阴影范围、模糊、overlay、sticky/fixed 线索；
7. **主题**：分别建立 surface/text/border/action/feedback 语义，不从一张主题图推另一主题；
8. **不确定性**：字体、DPR、隐藏状态、动效、响应式和交互不能从静态图确认时进入 gap。

颜色提取应同时保留原始采样点、出现区域、alpha 推断和聚类结果。几何测量应保存标注图到 `evidence/<theme>/annotated/`，机器测量保存到 `evidence/measurements/`。

### 5.3 截图输入后的主动请求

优先请求原始分辨率文件、同页另一主题、相同组件其他状态、相同页面其他视口、字体/图标文件和可访问 URL/源码。不要笼统问“还有资料吗”，要指出具体缺口对精确复刻的影响。

## 6. 用户提供源码时

### 6.1 先静态、后运行

1. 原样归档或记录用户原路径、版本/commit、哈希和许可证；不要改原件。
2. 列目录、识别技术栈、锁文件、构建工具和入口。
3. 先阅读 package scripts、安装脚本、容器文件和环境变量说明，评估风险。
4. 搜索设计来源：CSS variables、Sass/Less 变量、Tailwind/config、theme provider、design token、全局样式、字体声明、图标注册、组件库、Storybook、路由和视觉测试。
5. 使用 `rg`/AST 建立 `Token → 样式 → 组件 → 页面` 反向索引。
6. 找出主题切换、系统偏好、持久化和 SSR/首屏处理。
7. 找出 media/container query、spacing scale、z-index、motion 和 reduced-motion。
8. 识别第三方库默认值与产品自定义覆盖，不能把依赖库全部规则误归为产品风格。

### 6.2 源码分析产物

- Token 文件及引用图；
- 字体和图标清单；
- 路由/页面/组件清单；
- 组件 props、variants、states 与 theme 分支；
- 全局布局和断点；
- Storybook stories、测试和视觉快照索引；
- 未使用/遗留 Token 与当前生效规则的区分；
- 版本和构建条件。

### 6.3 安全运行与自动采集

只有静态检查通过后才考虑安装/运行：

- 优先使用现有依赖和锁文件；
- 在隔离副本中运行，不改归档原件；
- 不使用真实生产凭据；需要数据时使用公开 demo 或 mock；
- 记录命令、端口、commit、环境和任何临时 patch；
- 启动后按网站 URL 流程自动截取双主题、多视口、组件状态；
- 若有 Storybook，优先用它系统采集组件矩阵，再用真实页面验证组合效果；
- 将实际计算样式与源码 Token 交叉核对，发现未生效/覆盖值时记录冲突。

## 7. 用户提供录屏、PDF 或设计文件时

### 录屏

- 保存原件并用 `ffprobe` 记录分辨率、帧率、时长；
- 在状态变化前、峰值、结束点提取关键帧；
- 分析触发、延迟、duration、easing、位移、缩放、透明度和遮罩；
- 录屏帧受编码影响，颜色不能优先于原始截图/源码；
- 请求相同交互的 reduced-motion 行为或源码证据。

### PDF/设计文件

- 保留原件、页码/画板名和导出版本；
- 优先使用可读取属性的设计源文件，而不是只看低清预览；
- 提取组件、变量、样式、字体、颜色、约束和 prototype 状态；
- 每个导出截图关联画板/节点 ID；
- 区分已发布组件、局部 detached 实例和探索稿。

## 8. 混合输入的交叉验证

当同时有 URL、截图和源码时，不重复孤立分析：

- 源码/设计 Token给出候选精确值；
- 计算样式确认运行时实际值；
- 截图确认视觉结果和组合关系；
- 录屏确认时序与动效；
- 多页面确认规则是否全局稳定。

任何不一致都登记为冲突并查明版本、缓存、主题、断点、浏览器或 A/B 差异。

## 9. 探索日志格式

每轮追加到 `sources/exploration-log.md`：

```md
## EXP-YYYYMMDD-NN
- 输入：SRC-001, SRC-002
- 目标：补齐 dark 主题表单状态
- 环境：工具及版本、浏览器、OS、viewport、DPR
- 动作：访问/命令/脚本摘要
- 新增文件：相对路径
- 发现：可验证事实
- 限制：权限、工具、状态不可达
- 覆盖变化：新增哪些矩阵单元
- 新增/关闭 TODO：TODO-xxx
- 需要用户：REQ-xxx
```

自动脚本本身应保存到档案的 `examples/reference/` 或适当的工具脚本位置，并注明如何重跑；临时缓存不归档。

## 10. 探索后的主动询问

完成可行探索后，按 blocker → high → medium 排序，合并重复问题。每个 `REQ-*` 必须包含：

- 缺少的具体证据；
- Agent 已经尝试过什么；
- 为什么现有资料不能精确确定；
- 对复刻的影响；
- 用户最省力的提供方式；
- 收到后如何验收并关闭。

一次优先问 3–7 个最高价值问题，避免一次抛出几十个低价值问题。用户无法提供时保留缺口，继续非阻塞工作，但状态不得虚高。

## 11. 防止浅探索的终局检查

结束当轮前必须回答：

- 是否只看了首页而漏掉核心页面类型？
- 是否两主题都在相同页面/状态下采集？
- 是否只有截图而没有尝试计算样式/源码？
- 是否只有 default 而漏了 hover/focus/error/loading/open？
- 是否只截桌面而未探索真实断点？
- 是否确认字体实际加载而非 fallback？
- 是否区分产品自定义与第三方默认？
- 是否保存原件、哈希、环境和重跑步骤？
- 是否主动尝试关闭 gap 后才向用户提问？

任何否定答案都应产生 TODO，除非有明确且有证据的“不适用”结论。
