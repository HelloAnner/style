# 新业务严格复刻工作流

## 1. 启动门禁

收到“参考 `<style-id>`”后：

1. 进入目标子档案，先读 `AGENTS.md`；
2. 读 `manifest.json`，实际核对状态和入口文件；
3. 读 `README.md`、`quality/TODO.md`、`quality/gaps.md`；
4. 只有状态为 `complete` 且目标所需主题/组件在覆盖矩阵中完成，才进入无条件严格复刻；
5. 若不完整，列出与当前目标直接相关的缺口，询问用户是补充资料、允许明确推断，还是暂停；
6. 未经用户确认，不把带缺口实现描述为“完全一致”。

不要先写页面再回头看风格档案。

## 2. 建立业务语义映射

先创建目标业务映射表：

```md
| 新业务对象 | 档案语义/组件 | 目标主题 | 变体/状态 | 规则来源 | 缺口 |
```

业务词不同不代表设计角色不同。例如“创建订单”和“新建任务”都可能映射 `action.primary`。先复用现有语义、组件和模式，再考虑扩展。

## 3. 实现顺序

1. **环境固定**：框架、浏览器目标、字体、locale、DPR 和基准视口；
2. **资源**：加载准确字体、图标和允许复用的素材；验证没有 fallback；
3. **Token**：接入共享和目标主题 Token，禁止近似值；
4. **全局基础**：reset、canvas、字体渲染、focus、层级和主题初始化；
5. **布局 primitives**：容器、栅格、stack、inline、断点；
6. **组件 primitives**：文字、图标、按钮、输入、surface；
7. **复合组件**：导航、表格、表单、浮层、反馈；
8. **页面模式**：列表、详情、工作台、设置等；
9. **业务页面**：只在已有设计语法内组合；
10. **状态与边界**：loading、empty、error、long content、overflow、mobile；
11. **双主题**：若产品支持主题切换，所有页面和状态分别验收；
12. **视觉回归与偏差报告**。

## 4. 严格值规则

- 直接使用档案 Token，不肉眼抄近似 hex。
- 不用系统默认字体代替档案字体。
- 不用框架默认组件绕过 anatomy 和状态规则。
- 不新增 `#xxxxxx`、任意 px、shadow、radius 或 transition，除非映射到现有 Token或经批准的扩展。
- 图标必须来自指定体系或精确参数，不能因为含义相近就换不同描边风格。
- 组件 props 和 DOM 可以因技术栈不同，但呈现、状态和行为必须一致。
- 新业务数据不能迫使组件静默变形；按档案的换行、截断、扩展和溢出规则处理。

## 5. 主题规则

- 每个页面明确 `light` 或 `dark`，不得依赖未定义默认值。
- light 只读取 light 展开 Token，dark 只读取 dark 展开 Token。
- 同语义的两主题值来自 mapping，不通过运行时亮度算法临时生成，除非来源系统本来如此。
- 主题切换遵循档案的触发、持久化、系统偏好和首屏策略。
- 图片、Logo、插画、图标、代码块、图表、overlay 和阴影也检查主题变体。

## 6. 新场景与缺口

目标业务出现档案没有的场景时：

1. 查 `patterns.md` 是否可由已有组件组合；
2. 查来源证据是否存在未文档化的相似语义；
3. 若可主动访问来源，按主动探索流程补采；
4. 若不能，向用户请求目标来源系统中的对应页面/状态；
5. 用户允许扩展后，使用已知比例尺和语法提出 `Recommended` 方案；
6. 扩展写在目标业务偏差报告，默认不污染原档案。

## 7. 不静默修正

发现来源规则存在可访问性或技术风险时，提交两种明确结果：

- Strict：来源精确值及风险；
- Adjusted：建议值、原因和视觉差异。

由用户决定。没有确认时保留 Strict，不能以最佳实践为由偷偷改变。

## 8. 视觉验收

### 环境对齐

参考与实现使用相同：主题、路由/状态、viewport、DPR、浏览器版本、缩放、字体、locale、时区、数据长度和滚动位置。等待字体、图片和异步内容稳定。

### 检查顺序

1. 页面 canvas 与壳层；
2. 容器、栅格、比例和断点；
3. 字体和文本换行；
4. surface、text、border、icon 和 feedback 色；
5. spacing、size、radius、shadow；
6. 组件 anatomy 与状态；
7. 浮层和 z-index；
8. 动效和 reduced-motion；
9. 长内容、空、错、加载和窄屏。

### 自动比较

优先生成 baseline、actual、diff 和机器指标，保存工具版本和阈值。受浏览器抗锯齿影响时，可以对边缘差异采用经说明的容差，但：

- Token、几何和布局的目标仍是精确值；
- 所有非环境噪声差异必须修复或经用户批准；
- 不能用过大阈值让错误通过；
- “0 个未解释差异”比笼统“像素相似度 99%”更重要。

## 9. 交付的复刻报告

目标业务应生成一份 conformance/偏差报告：

- 使用的档案 ID、版本和 commit；
- 实现主题与页面范围；
- Token 和组件映射；
- 测试环境与视觉回归结果；
- 已通过的验收项；
- 未实现项、Recommended 扩展和用户批准偏差；
- 字体/素材授权限制；
- 最终结论：`exact within validated scope | partial | blocked`。

只有覆盖范围内没有未解释差异，才能用 `exact within validated scope`。
