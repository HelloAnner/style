# 待办、主动询问、自检与完成门槛

## 1. 状态模型

- `intake`：仅完成建档和输入登记；
- `inventoried`：完成页面、组件、主题、状态和资源盘点；
- `analyzed`：完成主要分析和初版 Token；
- `reusable`：另一个 Agent 可在明确缺口下使用；
- `validated`：关键范围完成可重复视觉验证；
- `complete`：全部硬门槛通过，开放待办为 0。

`reusable` 和 `validated` 都不等于完整。状态可以因新冲突或回归失败而回退。

## 2. TODO

从建档时创建 `quality/TODO.md`。每项格式：

```md
- [ ] TODO-001 `blocker | high | medium | low`
  - 范围：light | dark | shared
  - 缺少：具体资料、产物或验证
  - 影响：为什么阻止精确复刻
  - 负责：agent | user | both
  - 需要用户提供：若适用，给出最省力方式
  - 完成标准：可观察、可测试结果
  - 证据：待补或 SRC/EVD 编号
  - 关联请求：REQ-xxx 或无
```

完成后改 `[x]` 并补日期、证据、验证，不删除历史。`blocker` 阻止 complete；用户要求全部待办清零，因此其他优先级未关闭也阻止 complete。

## 3. REQUESTS 主动询问队列

`quality/REQUESTS.md` 记录需要用户介入的事项：

```md
## REQ-001 `open | answered | waived`
- 优先级：blocker
- 请求：请提供同一详情页 1440×900 的 dark 原图
- 已主动尝试：检查主题开关、系统偏好、源码和现有截图
- 原因：无法确认 dark overlay 与 border
- 提供方式：直接上传原图，或提供可访问 URL
- 收到后的完成标准：关闭 TODO-003 的对应矩阵单元
- 关联：TODO-003, GAP-002
```

Agent 必须先探索再问；问题按 blocker/high 排序，一轮集中问 3–7 个最高价值请求。避免“还有资料吗”这类无目标问题。用户暂时不能提供时，保留 open；用户明确接受缺口时标 `waived`，但关键缺口仍阻止完整状态。

## 4. gaps

`quality/gaps.md` 记录：未知事实、低置信结论、近似替代、冲突、权限/工具限制和授权风险。每项说明影响、当前证据、关闭路径及关联 TODO/REQ。gap 不是垃圾桶；每轮要尝试关闭或解释为何保留。

## 5. 三次自检

每轮至少执行：

1. 建档/接收输入后；
2. 分析和 Token 生成后；
3. 当轮结束或准备提升状态前。

最终记录在 `completion-report.md`：

- **证据**：关键值有无来源？推断是否伪装观察？
- **主动探索**：是否已用可用工具最大化探索，而不是过早问用户？
- **主题**：light/dark 证据、规则、Token、状态和验证是否分离且齐全？
- **覆盖**：页面、组件、状态、断点、字体、图标、动效是否有空白？
- **精确**：是否存在“约、大概、相似”、近似字体/颜色/间距？
- **一致**：JSON、CSS、主题展开、文档、示例是否一致？
- **冲突**：版本、断点、主题和状态差异是否解释？
- **消费**：另一个 AI 只看子文件夹是否能执行？子 `AGENTS.md` 是否有效？
- **验证**：是否双主题、多视口、可重复，而非主观判断？
- **待办**：失败项是否进入 TODO，用户阻塞项是否进入 REQUESTS？

## 6. complete 硬门槛

必须全部满足：

### 入口与来源

- 子档案 `AGENTS.md` 完整，可独立指导另一个 AI；
- 必需文件存在且非占位；
- 原件、哈希、来源、版本、授权和采集环境可追溯；
- 探索日志说明工具、范围和限制；
- capture manifest 有效。

### 双主题

- light/dark 都有相同核心页面和组件的来源证据；
- 两主题有独立分析、完整展开 Token/CSS 和映射；
- 两主题主要组件状态均覆盖；
- 没有反色推断冒充事实或跨主题误用。

### 设计系统

- 字体、图标、色彩、间距、尺寸、圆角、边框、阴影、布局、层级和动效有精确规则；
- 核心页面、组件、变体、状态和模式完整；
- desktop/mobile 和来源存在的其他强制断点已验证；
- JSON/CSS 有效，alias 可解析，聚合与主题展开一致；
- 无关键低置信、近似替代或未解释冲突。

### 验证

- light/dark 至少各完成一个典型 desktop 和 mobile 页面的可重复视觉回归；
- 核心组件状态矩阵完成验证；
- 测试环境、baseline、actual、diff 和结论可追溯；
- 所有非环境噪声差异已关闭或由用户显式批准；
- acceptance 全部通过。

### 待办

- TODO 中无 `[ ]`；
- REQUESTS 中无 open；
- manifest `openItems = 0`、`blockingItems = 0`；
- 最新 completion report 全部通过；
- manifest、README、AGENTS、CHANGELOG 状态一致。

不适用项不能删除，需写明证据和理由，经过自检后以 `[x] n/a` 关闭。

## 7. 完成报告最低内容

- 档案 ID/version/commit；
- 检查日期和 Agent/工具版本；
- 来源数量和覆盖率；
- light/dark 覆盖矩阵摘要；
- Token/CSS 校验结果；
- 视觉回归环境与结果；
- 自检逐项 pass/fail；
- TODO/REQUESTS 计数；
- 批准偏差；
- 最终状态和理由。

## 8. 回复用户

每轮简明报告：

1. 主动探索了什么；
2. 新保存了哪些原件和派生证据；
3. 双主题覆盖变化；
4. 生成/更新哪些规则；
5. 当前状态和完成率；
6. 仍开放的 blocker；
7. 最优先的 3–7 个用户请求及提供方式。

只有 `complete` 才能说“完整、可严格复刻”。其余必须说“部分完成/仍受以下证据限制”。
