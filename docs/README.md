# 设计风格档案规范索引

本目录是根 `AGENTS.md` 的详细执行手册。规范采用“入口简短、专题完整”的结构，避免把所有规则堆在一个文件中。

## 文档地图

| 文档 | 内容 | 何时必读 |
|---|---|---|
| `01-core-contract.md` | 严格复刻定义、主题原则、优先级 | 所有任务 |
| `02-profile-structure.md` | 子档案目录、最低产物、文件职责 | 新建/更新档案 |
| `03-active-exploration.md` | URL、截图、源码、设计稿的主动深度探索 | 采集/补充档案 |
| `04-evidence-analysis.md` | 来源、证据、测量、置信度、分析方法 | 采集/审核档案 |
| `05-design-system-spec.md` | 双主题、Token、组件、模式、实现文档 | 采集/实现 |
| `06-replication-workflow.md` | 另一个 AI 如何严格复刻到新业务 | 消费档案 |
| `07-quality-completion.md` | TODO、主动询问、自检、完整性门槛 | 所有任务 |

| `10-profile-agent-template.md` | 每个子档案 `AGENTS.md` 的模板 | 新建档案 |

## 强制阅读路由

### 用户给了网站 URL

依次完整阅读：`01 → 02 → 03 → 04 → 05 → 07 → 08 → 09`。

### 用户给了截图、录屏、PDF 或设计稿

依次完整阅读：`01 → 02 → 03 → 04 → 05 → 07 → 08 → 09`，重点执行 `03` 的媒体输入流程。

### 用户给了源码

依次完整阅读：`01 → 02 → 03 → 04 → 05 → 07 → 08 → 09`，先做安全静态检查，再决定是否运行。

### 用户要求参考某个子档案开发

先完整阅读该子档案的 `AGENTS.md`，然后读：`01 → 05 → 06 → 07 → 09`。若状态不是 `complete`，不得跳过缺口提示。

### 用户要求审核档案是否完整

阅读：`01 → 02 → 04 → 05 → 07 → 08`，逐项核验实际文件，不能只相信 manifest 自报状态。

## 规范优先级

1. 用户当轮明确要求；
2. 根目录 `AGENTS.md`；
3. 本目录专题规范；
4. 子档案 `AGENTS.md` 中针对该档案的具体约束；
5. 子档案中的设计规则与证据。

若上层规则要求严格复刻，而档案证据不足，下层不得用猜测绕过。应标记缺口并询问用户。

## 维护规则

- 调整目录、状态或 Schema 时，同步更新所有交叉引用和 `10-profile-agent-template.md`。
- 不创建内容重复但结论冲突的文档；每类规则指定一个权威文件。
- 专题文档可以继续拆分，但必须在本索引登记并注明任务路由。
- 每个子档案的内部文档是该风格事实的权威来源；本目录只规定采集和复刻方法，不存放某个具体风格的结论。
